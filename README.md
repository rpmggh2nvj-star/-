ブラウザだけで動く、1ファイル完結のHTMLアプリ集です。

| ファイル | 内容 |
| --- | --- |
| `keiba-yosou.html` | Turf Logic ／ 競馬予想アプリ（中央・南関対応） |
| `exam-planner.html` | Recurve ／ 試験対策プランナー |

## Turf Logic（競馬予想アプリ）

中央（JRA）10場と南関東（NAR）4場に対応した競馬予想アプリです。
出走馬のデータから指数・推定勝率・買い目を算出します。

使い方は2通りあります。

- **アプリ単体** … `keiba-yosou.html` をブラウザで開く。通信もインストールも不要。
  競馬新聞のPDFを選ぶか、出馬表をコピーして貼り付ければ自動で入力される
- **CLIと組み合わせ** … 保存した出馬表をPCで解析してJSONにし、アプリに読み込む

### 対応競馬場

| 区分 | 競馬場 |
| --- | --- |
| 中央（JRA） | 札幌・函館・福島・新潟・東京・中山・中京・京都・阪神・小倉 |
| 南関東（NAR） | 大井・川崎・船橋・浦和 |

南関4場はダートのみのため、選ぶと自動でダートに固定されます。
新潟・京都・阪神の芝は外回りを選べます。

## 1. アプリ単体で使う

`keiba-yosou.html` をブラウザで開き、レース設定と出走馬を入力して
「この条件で予想する」を押すだけです。まずは「サンプル読込」で
8頭立てのデモデータを入れると動作を確認できます。

### PDFから自動入力する

競馬新聞や出馬表をPDFで保存してあるなら、それを選ぶだけです。

1. アプリの **「出馬表を読み取る」** を押す
2. **「PDF」** タブを選ぶ
3. PDFファイルを選択

複数ページのPDFにも対応します。PDF内の文字の座標を使って元の表の行を
復元してから解析するため、レイアウトが崩れにくい作りです。

**netkeibaの馬柱形式**（1頭が6行のブロックで、父名・母名・過去4走が並ぶ形）は
表形式ではないため専用に解析します。この形式からは次が自動で入ります。

| 項目 | 備考 |
| --- | --- |
| 馬名 | 父名・母名・前走相手と取り違えない |
| 単勝オッズ・人気 | |
| 斤量 | ▲△などの減量記号を除いて数値化 |
| 脚質 | 逃・先・差・追 |
| 近走着順 | 過去3走 |
| 騎手名 | 紙面の表記に合わせて短縮形のことがある |
| 性齢 | |
| 競馬場・距離 | |
| 馬場適性・距離適性 | 過去走から推定（下記） |

**馬場適性・距離適性**は紙面に載っていないため、過去走から推定します。
道悪（稍重・重・不良）での着順、および今回と±200m以内の距離での着順を、
その馬自身の平均着順と比べます。絶対的な着順ではなく「自分の平均より
良いかどうか」で見るため、クラスの差に左右されにくくなります。
推定値なので、納得できなければ手で直してください。

今回の馬場状態は出走前のPDFには載っていないため、手で設定してください。

読み取りは端末の中だけで完結します（PDFはどこにも送信されません）。

**紙面をスキャンした画像だけのPDFは読み取れません。** 文字情報が
入っていないためで、その場合はその旨を表示します。PDFビューアで
文字を選択できるかどうかが目安です。

### 画像について

**画像を直接読み取ることはできません。** ブラウザ内で日本語を文字起こしする
手段がなく、必要なデータ（OCRエンジンと日本語学習データ）は数MB〜数十MBに
なるうえ、紙面のような密な表では誤読が避けられないためです。
誤読したオッズや着順は、そのまま誤った買い目につながります。

画像を貼り付けると、端末に入っている文字認識の使い方を案内します。
iPhoneの「テキスト認識表示」やAndroidのGoogleレンズは日本語の精度が高く、
そこでコピーした文字はこのアプリでそのまま読み取れます。

### 出馬表を貼り付けて自動入力する

1頭ずつ手で入れる代わりに、出馬表をコピーして貼り付けられます。

1. 出馬表のページで、表の部分を選択してコピー
2. アプリの **「出馬表を読み取る」** を押す
3. 貼り付けて **「読み取る」**

馬番・馬名・単勝オッズ・斤量・馬体重増減・性齢と、
競馬場・距離・馬場状態が自動で入ります。何頭ぶんの何が取れたかは
その場に表示されるので、取りこぼしがあればすぐ分かります。

**近走着順と脚質は出馬表から一意に決められないため、手で入れてください。**
この2つが予想の精度を大きく左右します（未入力だと、アプリはオッズ通りの
評価しか返しません。後述の「情報量」を参照）。

PCもファイル保存も不要なので、スマホだけで完結します。

### 騎手評価

出馬表から騎手名が読み取れると「騎手評価」の一覧が出ます。
ここで一度つけた評価は端末に記憶され、**次回以降その騎手が出てきたら
自動で入ります**。同じ騎手が複数の馬に乗る場合もまとめて反映されます。
南関のように同じ騎手が繰り返し乗る開催では、数レースでほぼ入力不要になります。

入力内容は「保存」「呼出」で端末に残せます（localStorageのみ。外部に送信しません）。

## 2. CLIで出馬表を解析する

Node.js が入ったPCで、保存した出馬表ファイルをまとめて処理したい場合の
補助ツールです。アプリの貼り付け機能と読み取り結果は同じなので、
ふだん使いはアプリだけで足ります。

```bash
# 保存した出馬表を解析して、そのまま予想を表示
node keiba/yosou.js racecard.html

# 条件を上書きしつつ、アプリ用のJSONを書き出す
node keiba/yosou.js racecard.txt --track 大井 --pace high --budget 10000 --out race.json

# 標準入力からも読める
cat racecard.txt | node keiba/yosou.js -
```

書き出した `race.json` は、アプリの「JSON読込」ボタンから取り込めます。

### 入力に渡すもの

次のいずれかを渡してください。

- 競馬新聞や出馬表を保存した **PDF**
- ブラウザで開いた出馬表ページを**保存したHTML**
- 画面から**コピーしたテキスト**

CLIはサイトを自動巡回しません。netkeiba をはじめ多くの競馬サイトは
利用規約で自動取得（スクレイピング）を禁止しているためです。
解析するのは、あくまで手元にあるファイルだけです。

### 取り出せる項目

パーサーはサイトごとのCSSセレクタに依存せず、表記のパターンから拾います。
そのため対応サイトを限定せず、レイアウト変更にも比較的強い作りです。

| 項目 | 取得 |
| --- | --- |
| 馬番・馬名 | ○（枠番と並んでいても馬番を判別） |
| 単勝オッズ | ○ |
| 斤量 | ○（オッズと数値域が重なっても取り違えないよう判定） |
| 馬体重・増減 | ○ |
| 性齢 | ○ |
| 競馬場・距離・馬場状態・R | ○（本文から自動判定。`--track` 等で上書き可） |
| 脚質 | ○（`逃` `先` `差` `追` などが載っている場合） |
| 近走着順 | ○（`1着` 形式などが載っている場合。中止・取消は出走なし扱い） |
| 騎手評価・調教評価・距離/馬場適性 | ✕（判断が入るため既定値） |

取得できなかった項目は必ず警告として表示されます。

出馬表のコピーは、行ごとに並ぶ場合と**列ごとに並ぶ場合**（馬名がN個続いた
あとに斤量がN個続く形。スマホで多い）があります。両方で解析して、
より多く読み取れた方を採用します。列方向のときは位置で対応づけるため、
人気とオッズの順位が一致するかを検算し、食い違えば警告します。

### 主なオプション

```
--track <名>      競馬場（例: 東京 / 大井）。未指定なら本文から自動判定
--surface <芝|ダート>
--distance <m>
--condition <良|稍重|重|不良>
--course outer    外回り（新潟・京都・阪神の芝）
--pace <ハイ|平均|スロー>   未指定なら脚質構成から自動判定
--budget <円>     既定 5000
--out <file.json> アプリに読み込めるJSONを書き出す
--json            解析結果のJSONだけを標準出力に出す
```

## 予想ロジック

### 能力指数

オッズを**除いた**以下の要素を加点・減点して算出します。

| 要素 | 内容 |
| --- | --- |
| 近走フォーム | 前走・2走前・3走前の着順を 5:3:2 で加重 |
| 騎手／調教 | S〜Dの5段階評価 |
| 距離適性／馬場適性 | ◎○△×の4段階。馬場適性は道悪ほど比重が上がる |
| 展開 | 想定ペース × 脚質 × **コース形態** |
| 斤量 | 出走馬平均との差 |
| 馬体重増減 | −4〜+8kg を適正圏とし、外れるほど減点 |
| 枠順 | コースの直線長に応じて内外の有利不利を調整 |

**コース形態**は各競馬場の直線距離から求めます。直線が長いほど差し・追込が、
短いほど逃げ・先行が有利になります（東京芝526m ⇔ 浦和220m）。
南関の小回りダートは前が止まりにくいため、逃げ・先行にさらに加点します。
枠順も同様で、小回りほど内枠有利が強まります。

### 推定勝率

能力指数を softmax で勝率に変換し、オッズから求めた市場推定勝率と
**幾何ブレンド**して最終的な推定勝率とします。

重要なのは、**市場側の重みが入力の情報量に応じて変わる**点です。

```
市場の重み = 1 − 0.45 × 情報量        （情報量 0 → 1.00 / 1.0 → 0.55）
```

近走着順や脚質が未入力だと能力指数はほぼ横並びになります。この状態で
市場と機械的にブレンドすると、人気薄が理由もなく持ち上がり
「妙味」の偽シグナルが出てしまいます。情報量が乏しいときは市場（オッズ）
そのものに収束させることで、根拠のない推奨を出さないようにしています。

情報量が35%未満のときは、アプリ・CLIともにその旨を明示します。

### 結果の見方

- **指数** … オッズを除いた能力評価
- **推定勝率** … 指数にオッズを加味した最終予想
- **期待値** … 推定勝率 × 単勝オッズ（単勝の期待回収率）
- **市場比** … 推定勝率 ÷ 市場推定勝率。1.00 超で「人気以上に評価できる馬」＝妙味

上位5頭に ◎○▲△△ の印を付け、市場比1.20以上の馬に「妙味」、
0.80以下の馬に「過剰人気」のタグを表示します。

### 買い目

◎を軸に、単勝・複勝・馬連流し・ワイド・三連複（軸1頭流し）を提案し、
予算を券種ごとに配分して1点あたりの金額まで表示します。
1点100円が最低単位のため予算に収まらない場合は、優先度の低い券種から
自動的に除外します（単勝は最後まで残ります）。

## 開発

```
keiba/
  engine.js        予想ロジック（正）。CLIとアプリの両方が読む
  parse.js         出馬表パーサー（行方向・列方向の両対応）
  pdftext.js       PDFのテキスト要素を座標から行に復元する
  yosou.js         CLI
  build.js         HTMLアプリのビルド
  ui/              アプリのUI（style / body / app）
  vendor/          pdf.js（同梱。keiba/vendor/README.md 参照）
  test/            テスト
```

`keiba-yosou.html` と `artifact-keiba.html` は **`keiba/build.js` の生成物**です。
直接編集せず、`keiba/engine.js` と `keiba/ui/*` を編集してビルドしてください。
予想ロジックを1か所に保つことで、CLIとアプリの計算が食い違わないようにしています。

```bash
node keiba/build.js            # HTMLアプリを生成
node keiba/test/engine.test.js # 予想エンジンのテスト
node keiba/test/parse.test.js  # パーサーのテスト
node keiba/test/pdf.test.js    # PDF読み取りのテスト
```

PDF読み取りには pdf.js を同梱しています。ブラウザでは Worker を起こさず
メインスレッドで動かしています。アーティファクトのCSPが Worker と blob: を
許可しないためで、同等のCSPを付けた環境で動作を確認済みです。

## 注意

指数・推定勝率はあくまで入力値をもとにした簡易モデルによる計算結果であり、
的中を保証するものではありません。馬券の購入は自己責任・余裕資金の範囲で行ってください
（20歳未満は購入できません）。
