## Turf Logic（競馬予想アプリ）

中央（JRA）10場と地方競馬14場に対応した競馬予想アプリです。
出走馬のデータから指数・推定勝率・買い目を算出します。

使い方は2通りあります。

- **アプリ単体** … `keiba-yosou.html` をブラウザで開く。通信もインストールも不要。
  競馬新聞のPDFを選ぶか、出馬表をコピーして貼り付ければ自動で入力される
- **CLIと組み合わせ** … 保存した出馬表をPCで解析してJSONにし、アプリに読み込む

### 対応競馬場

| 区分 | 競馬場 |
| --- | --- |
| 中央（JRA） | 札幌・函館・福島・新潟・東京・中山・中京・京都・阪神・小倉 |
| 南関東 | 大井・川崎・船橋・浦和 |
| その他の地方 | 門別・盛岡・水沢・金沢・笠松・名古屋・園田・姫路・高知・佐賀 |

芝コースを持たない競馬場を選ぶと、自動でダートに固定されます
（地方では盛岡だけが芝を持ちます）。新潟・京都・阪神の芝は外回りを選べます。

ばんえい（帯広）は直線200mでソリを曳く競走のため、周回コースを前提とした
このモデルが当てはまりません。対象外にしています。

## 1. アプリ単体で使う

`keiba-yosou.html` をブラウザで開き、レース設定と出走馬を入力して
「この条件で予想する」を押すだけです。まずは「サンプル読込」で
8頭立てのデモデータを入れると動作を確認できます。

### PDFから自動入力する

競馬新聞や出馬表をPDFで保存してあるなら、それを選ぶだけです。

1. アプリの **「出馬表を読み取る」** を押す
2. **「PDF」** タブを選ぶ
3. PDFファイルを選択

複数ページのPDFにも対応します。PDF内の文字の座標を使って元の表の行を
復元してから解析するため、レイアウトが崩れにくい作りです。

**netkeibaの馬柱形式**（1頭が6〜7行のブロックで、父名・母名・過去4走が並ぶ形）は
表形式ではないため専用に解析します。この形式からは次が自動で入ります。

| 項目 | 備考 |
| --- | --- |
| 馬名 | 父名・母名・レース名・前走相手と取り違えない |
| 単勝オッズ・人気 | |
| 斤量 | ▲△などの減量記号を除いて数値化 |
| 脚質 | 逃・先・差・追 |
| 近走着順 | 過去3走。除外・中止も1走として位置を残す |
| 騎手名 | 紙面で切れた表記は、過去走の欄に載る長い表記に自動で直す |
| 性齢 | |
| 出走取消・除外 | 印の欄から判定し、予想の対象から外す |
| 競馬場・距離 | |
| 馬場適性・距離適性 | 過去走から推定（下記） |

馬名の行は「父名の行のすぐ下」で判別します。行の中身だけで見分けようとすると、
過去走のレース名（「ロードカナロア賞」が紙面で「ロードカナ」に切れる、など）を
馬名として拾ってしまうためです。

**騎手名**は今回の欄が狭く、「小野楓馬」が「小野楓」で切れて印刷されます。
切れたままだと同じ騎手が別人として記憶され、評価が引き継がれません。
過去走の欄には長い表記が載るので、それを辞書として名前を伸ばします。
伸ばす先が2つ以上ある名前（「山本聡」が山本聡紀にも山本聡哉にも当てはまる、など）は、
別人にしてしまわないよう切れたまま残し、候補を挙げて報告します。
読み取った表記はこの端末に貯まり、次に別の出馬表で切れた名前が出てきたときにも使われます。

騎手欄そのものを取りこぼす紙面もありました。原因は3つあり、いずれも直してあります。

| 紙面 | 取りこぼしの原因 |
| --- | --- |
| 外国産馬 | 母名が `Sea Chanter (War Chant)` とローマ字。母名行をカタカナ限定で判定していた |
| 「佐々木」 | `々` が漢字の範囲(`一-龥`)に入らず、人名として通らなかった |
| 印の欄が無い紙面 | 母名行が見つからないと騎手も落ちるため、アンカーの直上の行で拾い直す |

**今回の馬体重**は、発走前の紙面には載っていません（過去走の馬体重は載っています）。
前走の値を各馬の欄に目安として出すので、当日発表されたら「馬体重」に入れてください。
**増減は前走との差から自動で計算されます**。紙面に今回の値が載っていれば、そのまま読み取ります。

**馬場適性・距離適性**は紙面に載っていないため、過去走から推定します。
道悪（稍重・重・不良）での着順、および今回と±200m以内の距離での着順を、
その馬自身の平均着順と比べます。絶対的な着順ではなく「自分の平均より
良いかどうか」で見るため、クラスの差に左右されにくくなります。
推定値なので、納得できなければ手で直してください。

今回の馬場状態は出走前のPDFには載っていないため、手で設定してください。

読み取りは端末の中だけで完結します（PDFはどこにも送信されません）。

**紙面をスキャンした画像だけのPDFは読み取れません。** 文字情報が
入っていないためで、その場合はその旨を表示します。PDFビューアで
文字を選択できるかどうかが目安です。

### 画像

「画像」タブから画像を選ぶ、または貼り付けると、**入力しながら見比べられるよう
画面上部に表示**します。拡大・スクロールできるので、手入力の助けになります。

**画像から自動で読み取ることはしていません。** ブラウザ内で動かせる日本語OCR
（tesseract.js）を実測したところ、実用に耐えませんでした。

きれいに描画した出馬表を2倍解像度で書き出した画像で検証した結果です。

| 項目 | 正しい値 | OCRの結果 |
| --- | --- | --- |
| 距離 | 1600m | `16600m` |
| 馬名 | アマゴ | `ゴー` |
| 馬名 | カナーリオ | `好 ー リ オォ` |
| オッズ・人気 | 50.0 / 5 | `48002 8005` |
| 斤量 | 54.0 | `40` |

主要9項目のうち正解は1つだけでした（2MBの軽量モデル）。16MBのフルモデルでは
0/9とさらに悪化し、「馬→和」「牝→和」のように漢字も崩れます。
**数字がほぼ壊れる**のが致命的で、誤読したオッズはそのまま誤った買い目に
なります。6.5MBの容量増と引き換えにこれを載せる価値はないと判断しました。

端末に入っている文字認識（iPhoneの「テキスト認識表示」、AndroidのGoogleレンズ）は
日本語の精度がはるかに高く、そこでコピーした文字はこのアプリでそのまま読み取れます。
手順は「画像」タブの中に載せてあります。

### 出馬表を貼り付けて自動入力する

1頭ずつ手で入れる代わりに、出馬表をコピーして貼り付けられます。

1. 出馬表のページで、表の部分を選択してコピー
2. アプリの **「出馬表を読み取る」** を押す
3. 貼り付けて **「読み取る」**

馬番・馬名・単勝オッズ・斤量・馬体重増減・性齢と、
競馬場・距離・馬場状態が自動で入ります。何頭ぶんの何が取れたかは
その場に表示されるので、取りこぼしがあればすぐ分かります。

**近走着順と脚質は出馬表から一意に決められないため、手で入れてください。**
この2つが予想の精度を大きく左右します（未入力だと、アプリはオッズ通りの
評価しか返しません。後述の「情報量」を参照）。

PCもファイル保存も不要なので、スマホだけで完結します。

### 出走取消・除外

出走馬の各カードにある **「取消」** にチェックを入れると、その馬は
予想の対象から外れます。単に削除するのと違い、取消だったことが画面に残ります。

- 推定勝率は残りの馬だけで合計100%になります（取消馬の人気ぶんが残りに配分されます）
- 買い目にその馬番は出ません
- 想定ペースの自動判定でも数えません

PDFに「取消」「除外」と載っていれば、読み取り時に自動でチェックが入ります。

### 騎手評価

出馬表から騎手名が読み取れると「騎手評価」の一覧が出ます。
ここで一度つけた評価は端末に記憶され、**次回以降その騎手が出てきたら
自動で入ります**。同じ騎手が複数の馬に乗る場合もまとめて反映されます。
南関のように同じ騎手が繰り返し乗る開催では、数レースでほぼ入力不要になります。

#### 評価の目安

「評価の目安」を開くと、S〜Dが勝率のどのあたりを指すかを確認できます。

| 評価 | 勝率の目安 |
| --- | --- |
| S | 20%以上（リーディング上位） |
| A | 13〜20% |
| B | 7〜13%（既定値） |
| C | 3〜7% |
| D | 3%未満（経験が浅い・減量騎手） |

さらに、後述の「予想の記録」に着順を入れていくと、**各騎手の成績が自動で集計**され、
一覧に「12戦 勝率25% 複勝25%」のように表示されます。10回以上の騎乗があれば
評価を提案し、ボタン1つで適用できます。10回未満で提案しないのは、
数レースの勝率がほとんど偶然で決まるためです。

### 記録は更新をまたいで残ります

アプリを更新すると記録に持たせる項目が増えます（レース評価・荒れ度など）。
すでに端末に保存されている記録はその項目を持ちませんが、**消したり作り直したり
しません**。読み込み時に形だけ揃え、当時なかった項目は `null` のままにします。

- 過去の予想を新しい基準で判定し直すことはしません（当時の予想は当時のまま）
- 壊れて読めない記録があっても、他の記録は残します
- 荒れ度を持たない記録は、荒れ度の集計からは除外します（他の集計には入ります）

### 予想の記録

予想したあと「この予想を記録する」を押すと、レース条件・予想順位・買い目が
端末に保存されます。**競馬場ごとに絞り込んで、いつでも見返せます。**

各記録に**着順（1〜3着の馬番）**を入れると、次が集計されます。

- ◎の勝率（◎が1着だった割合）
- ◎の複勝率（◎が3着以内だった割合）
- 上位3頭に1着馬が入った割合

この着順は騎手成績の集計にも使われます。予想に載った全馬の騎手を数えるため、
予想が当たったかどうかとは独立した「その騎手自身の成績」になります。

記録は最大300件まで保存され、古いものから消えます。

入力内容は「保存」「呼出」で端末に残せます（localStorageのみ。外部に送信しません）。

## 2. CLIで出馬表を解析する

Node.js が入ったPCで、保存した出馬表ファイルをまとめて処理したい場合の
補助ツールです。アプリの貼り付け機能と読み取り結果は同じなので、
ふだん使いはアプリだけで足ります。

```bash
# 保存した出馬表を解析して、そのまま予想を表示
node keiba/yosou.js racecard.html

# 条件を上書きしつつ、アプリ用のJSONを書き出す
node keiba/yosou.js racecard.txt --track 大井 --pace high --budget 10000 --out race.json

# 標準入力からも読める
cat racecard.txt | node keiba/yosou.js -
```

書き出した `race.json` は、アプリの「JSON読込」ボタンから取り込めます。

### 入力に渡すもの

次のいずれかを渡してください。

- 競馬新聞や出馬表を保存した **PDF**
- ブラウザで開いた出馬表ページを**保存したHTML**
- 画面から**コピーしたテキスト**

CLIはサイトを自動巡回しません。netkeiba をはじめ多くの競馬サイトは
利用規約で自動取得（スクレイピング）を禁止しているためです。
解析するのは、あくまで手元にあるファイルだけです。

### 取り出せる項目

パーサーはサイトごとのCSSセレクタに依存せず、表記のパターンから拾います。
そのため対応サイトを限定せず、レイアウト変更にも比較的強い作りです。

| 項目 | 取得 |
| --- | --- |
| 馬番・馬名 | ○（枠番と並んでいても馬番を判別） |
| 単勝オッズ | ○ |
| 斤量 | ○（オッズと数値域が重なっても取り違えないよう判定） |
| 馬体重・増減 | ○ |
| 性齢 | ○ |
| 競馬場・距離・馬場状態・R | ○（本文から自動判定。`--track` 等で上書き可） |
| 脚質 | ○（`逃` `先` `差` `追` などが載っている場合） |
| 近走着順 | ○（`1着` 形式などが載っている場合。中止・取消は出走なし扱い） |
| 出走取消・除外 | ○（オッズ欄などに `取消` `除外` があれば取消として扱う） |
| 騎手評価・調教評価・距離/馬場適性 | ✕（判断が入るため既定値） |

取得できなかった項目は必ず警告として表示されます。

出馬表のコピーは、行ごとに並ぶ場合と**列ごとに並ぶ場合**（馬名がN個続いた
あとに斤量がN個続く形。スマホで多い）があります。両方で解析して、
より多く読み取れた方を採用します。列方向のときは位置で対応づけるため、
人気とオッズの順位が一致するかを検算し、食い違えば警告します。

### 主なオプション

```
--track <名>      競馬場（例: 東京 / 大井）。未指定なら本文から自動判定
--surface <芝|ダート>
--distance <m>
--condition <良|稍重|重|不良>
--course outer    外回り（新潟・京都・阪神の芝）
--pace <ハイ|平均|スロー>   未指定なら脚質構成から自動判定
--budget <円>     既定 5000
--out <file.json> アプリに読み込めるJSONを書き出す
--json            解析結果のJSONだけを標準出力に出す
```

## 予想ロジック

### 能力指数

オッズを**除いた**以下の要素を加点・減点して算出します。

| 要素 | 内容 |
| --- | --- |
| 近走フォーム | 前走・2走前・3走前の着順を 5:3:2 で加重 |
| 騎手／調教 | S〜Dの5段階評価 |
| 距離適性／馬場適性 | ◎○△×の4段階。馬場適性は道悪ほど比重が上がる |
| 展開 | 想定ペース × 脚質 × **コース形態** |
| 斤量 | 出走馬平均との差 |
| 馬体重増減 | −4〜+8kg を適正圏とし、外れるほど減点 |
| 枠順 | コースの直線長に応じて内外の有利不利を調整 |

**コース形態**は各競馬場の直線距離から求めます。直線が長いほど差し・追込が、
短いほど逃げ・先行が有利になります（東京芝526m ⇔ 浦和220m）。
南関の小回りダートは前が止まりにくいため、逃げ・先行にさらに加点します。
枠順も同様で、小回りほど内枠有利が強まります。

### 推定勝率

能力指数を softmax で勝率に変換し、オッズから求めた市場推定勝率と
**幾何ブレンド**して最終的な推定勝率とします。

重要なのは、**市場側の重みが入力の情報量に応じて変わる**点です。

```
市場の重み = 1 − 0.45 × 情報量        （情報量 0 → 1.00 / 1.0 → 0.55）
```

近走着順や脚質が未入力だと能力指数はほぼ横並びになります。この状態で
市場と機械的にブレンドすると、人気薄が理由もなく持ち上がり
「妙味」の偽シグナルが出てしまいます。情報量が乏しいときは市場（オッズ）
そのものに収束させることで、根拠のない推奨を出さないようにしています。

情報量が35%未満のときは、アプリ・CLIともにその旨を明示し、**そのレースは見送りにします**（後述）。

### 結果の見方

- **指数** … オッズを除いた能力評価
- **推定勝率** … 指数にオッズを加味した最終予想
- **期待値** … 推定勝率 × 単勝オッズ（単勝の期待回収率）
- **市場比** … 推定勝率 ÷ 市場推定勝率。1.00 超で「人気以上に評価できる馬」＝妙味

上位5頭に ◎○▲△△ の印を付け、**期待値1.10以上**の馬に「妙味」、
**0.70以下**の馬に「過剰人気」のタグを表示します。

判定に市場比ではなく期待値を使うのは、控除率のぶんの下駄があるためです。

```
期待値 = 推定勝率 × オッズ = 市場比 ÷ Σ(1/オッズ)
```

`Σ(1/オッズ)` は控除率の逆数（中央 約1.19／地方 約1.25）です。つまり
**市場比1.20倍は、期待値でいえばちょうど1.0前後＝やっと元が取れる水準**でしかなく、
これを妙味と呼んで買い続けると負けます。

比率だけでは判定しません。**勝率で0.5ポイント以上の差**があることも条件です。
300倍の馬の0.25%が0.40%になっても比率は1.6倍ですが、差は0.15ポイントしかなく、
モデルにその精度はないためです。

### softmaxの温度

能力指数を勝率に変換するときの温度は固定せず、**指数の広がりが市場の広がりと
釣り合うように**毎レース決めています（下限4・上限14）。

温度を大きめに固定するとモデルの勝率が中央に潰れ、「勝ち目のない馬」を
表現できなくなります。するとブレンドで極端な人気薄が機械的に持ち上がり、
300倍の馬に「妙味」が付くという誤りが出ます。実際、固定値では
モデルの対数勝率の広がりが市場の3分の1以下に潰れていました。

### 買うべきレースかどうか

日本の馬券は控除率が20〜25%あります。**市場をなぞるだけの予想では、買った時点で
必ず負けます**。したがって最初に判定すべきは「どの馬を買うか」ではなく
「そもそもこのレースを買うか」です。予想結果の先頭に次の4段階で表示します。

| 判定 | 条件 | 投入額 |
| --- | --- | --- |
| **見送り推奨** | 情報量35%未満（＝オッズのなぞり） | 0円 |
| **見送り推奨** | 期待値1.0を超える馬が1頭もいない | 0円 |
| **小額なら** | 最良の期待値が1.0〜1.08 | 予算の30% |
| **買える（控えめに）** | 最良の期待値が1.08〜1.20 | 予算の60% |
| **勝負できる** | 期待値1.20以上＋情報量60%以上＋妙味馬あり | 予算の100% |

見送りのときは買い目を一切出しません。推定勝率が4%未満の馬はモデルの精度を
超えるため、期待値の判定から除きます。

### 荒れ度（レースが荒れたときの対処）

レースが荒れるのは偶然だけではなく、荒れやすい条件があります。予想とは別に
そのレースの崩れやすさを 0〜100 で出し、買い方をそれに合わせます。

| 材料 | 重み | 見方 |
| --- | --- | --- |
| 混戦度 | 0.34 | 推定勝率のエントロピー。横一線に近いほど高い |
| ペース崩壊 | 0.20 | 逃げ馬の数。3頭以上で前が総崩れになりやすい |
| 道悪 | 0.18 | 稍重・重・不良。能力より馬場適性が効き、実績どおりに走らない |
| 多頭数 | 0.10 | 頭数が増えるほど道中の不利を受ける馬が増える |
| 1番人気の危うさ | 0.18 | 1番人気の期待値が1を割るほど、人気を被っていて崩れやすい |

| 荒れ度 | 相手 | 三連複 | 投入額 | 単勝の比重 |
| --- | --- | --- | --- | --- |
| **堅い**（35未満） | 2頭 | 出さない | そのまま | 30% |
| **やや荒れる**（35〜60） | 3頭 | 出す | ×0.9 | 25% |
| **荒れやすい**（60以上） | 5頭 | 出す | **×0.7** | 18% |

考え方の要点は、**荒れそうなときに強気にならない**ことです。荒れるレースでは
推定勝率そのものが当てにならなくなります。したがって点数は広げますが、
**投入額はむしろ絞ります**（点数を広げることと、賭け金を増やすことは別の話です）。

荒れやすいと判定した理由と、その場合の具体的な買い方を画面に並べて出します。

#### 読みが当たっているかの検算

「荒れやすい」と読んだレースが実際に荒れたのかを確かめられないと、この指標を
信用してよいか判断できません。着順を記録すると、荒れ度の段階ごとに
**実際に荒れた割合**を集計して表示します。1着馬が予想4位以下だったか、
または10倍以上の人気薄だったときを「荒れた」と数えます。

### 買い目

**単勝は、期待値が1.0以上の馬にしか買いません。** 本命だからという理由では買いません。
入力されたオッズから期待値をそのまま計算できるのは単勝だけなので、ここは厳密に扱います。
期待値の高い順に最大2頭まで買います。

**軸は、上位3頭のうち期待値がいちばん高い馬**にします。軸はすべての買い目に入るため、
人気を被った馬（期待値が1を大きく割る馬）を軸にすると全点数がその不利を被ります。

**相手の頭数は荒れ度で決めます**（上表）。堅いレースで手広く流すと、点数だけ増えて
必要オッズが跳ね上がり割に合いません。

#### 必要オッズ

馬連・ワイド・三連複は**そのオッズを入力していないため、期待値を計算できません**。
代わりに的中確率から「これ以上のオッズが付いていれば買ってよい」という
**必要オッズ**を出します。n点を同額で買う場合、

```
必要オッズ（平均） = 点数 ÷ 的中確率の合計
```

を下回るオッズしか付いていないなら、その買い目は見送りです。買う前に
手元のオッズと見比べてください。

的中確率は **Harville モデル**（1着馬を除いた残りで、同じ比率のまま2着が決まると
仮定する標準的な近似）で計算しています。人気薄ほど複勝率が高く出る傾向があり、
この近似はそれを過小評価します。必要オッズも同じだけの誤差を含みます。

複勝・ワイド・三連複は発売条件（複勝は5頭以上、ワイド・三連複は4頭以上）を
満たすときだけ提案します。予算に収まらない場合は優先度の低い券種から自動的に
除外します（単勝は最後まで残ります）。

## 開発

```
keiba/
  engine.js        予想ロジック（正）。CLIとアプリの両方が読む
  parse.js         出馬表パーサー（行方向・列方向の両対応）
  pdftext.js       PDFのテキスト要素を座標から行に復元する
  history.js       予想の記録の集計（成績・騎手成績・評価の提案）
  yosou.js         CLI
  build.js         HTMLアプリのビルド
  ui/              アプリのUI（style / body / app）
  vendor/          pdf.js（同梱。keiba/vendor/README.md 参照）
  test/            テスト
```

`keiba-yosou.html` と `artifact-keiba.html` は **`keiba/build.js` の生成物**です。
直接編集せず、`keiba/engine.js` と `keiba/ui/*` を編集してビルドしてください。
予想ロジックを1か所に保つことで、CLIとアプリの計算が食い違わないようにしています。

```bash
node keiba/build.js            # HTMLアプリを生成
node keiba/test/engine.test.js # 予想エンジンのテスト
node keiba/test/parse.test.js  # パーサーのテスト
node keiba/test/pdf.test.js    # PDF読み取りのテスト
node keiba/test/history.test.js # 記録と集計のテスト
```

PDF読み取りには pdf.js を同梱しています。ブラウザでは Worker を起こさず
メインスレッドで動かしています。アーティファクトのCSPが Worker と blob: を
許可しないためで、同等のCSPを付けた環境で動作を確認済みです。
